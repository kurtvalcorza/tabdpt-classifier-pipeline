## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6) and isolated environment (RUN1, RUN10, ENV6):** the primary path performs no clone, repository install or repository import, and installs nothing into the notebook kernel. Section 2 of the notebook writes `src/tabdpt_classifier_pipeline/{__init__,pipeline,artifact,dimer_runtime}.py`, the notebook's stage runner, the hash-locked `requirements-colab.lock.txt`, the one-file SHA-256 snapshot manifest and the licence into a run directory and verifies each against its SHA-256 (`CARRIED_HASHES`); a pinned `uv` wheel (size + SHA-256) builds a managed-CPython virtual environment from the lock with `--require-hashes`, keyed on the lock's digest so a second Run all reuses it, and every learner cell runs one stage of the stage runner in its own process (`run_stage`). Re-running the Section 1 cell keeps the run directory. `metadata.dimer.generated_from` records the repository, the generating commit, the package SHA-256, the carried-file digests and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file (package module, stage runner, lock, manifest) differs from the repository, when the lock does not pin every `pyproject.toml` runtime pin with hashes, or when a notebook is not byte-identical to the generator's output for its template.
- **Model acquisition:** the `weights` stage writes the carried manifest into `weights/tabdpt-1.2/`; `stage_missing_files(..., allow_download=True)` fetches only the manifest entry that is absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes it and asserts the manifest digest equals the package's `TABDPT_WEIGHT_SHA256`; each later stage builds its pipeline with `from_pretrained(weights_dir=..., compile_model=False, use_flash=False, seed=42)`, which pins the verified file as the base checkpoint (the model is constructed inside `fit` / `load_verified_artifact`). The notebooks' only external dependencies are PyPI (the `uv` wheel and the locked packages), the managed CPython build `uv` downloads, and the Hub at that revision.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/<stem>_input_manifest.json` with the schema, observed table structure, verdict and one recorded rejection finding; `evaluation_report` (EVAL21) writes `outputs/<stem>_evaluation_report.json` — `sample-sanity` with `accuracy` / `log_loss` / `roc_auc` and the majority-class baseline.
- **External-artifact section (§19.1, XAS1–XAS7, SART1–SART11):** Section 10 needs only the setup cells (Sections 1–3). Its default artifact is pinned by URL and SHA-256 in the stage runner (`SAMPLE_ARTIFACT_URL`, `SAMPLE_ARTIFACT_SHA256`); the digest is checked before extraction, the ZIP must hold exactly `artifact.json` and `training_context.parquet` at its root, `validate_artifact_bundle` runs before any model state is reconstructed, the artifact must follow the breast-cancer default path's data contract (SART10), and `load_verified_artifact` takes the base checkpoint from the Section 3 snapshot and fails closed on the legacy reconditioning path. A failed check stops the run before any prediction file is written. The location field is a dropdown (`ARTIFACT_SOURCE`) defaulting to the pinned asset, because notebook cells may carry no `github.com/kurtvalcorza` URL (ST1); the validator allows exactly that one URL, whole, in the stage runner only.
- Classification obligations (Notebook Specification §20.1): class labels and counts are printed before the model runs, the decision rule is `argmax`, probabilities are described as uncalibrated (no threshold is shipped; downstream calibration is the caller's), and exported `proba_<class>` columns keep the sorted class order in both CSV and JSON.
- `USE_BYOD`, `ARTIFACT_SOURCE` and `USE_OWN_ROWS` default to the sample path, which opens no upload dialog. Each optional branch accepts a path (`BYOD_PATH`, `ARTIFACT_ZIP_PATH`, `EXTERNAL_ROWS_PATH`) that works outside Colab.

## Preprocessing and capacity semantics

For TabDPT, `fit()` performs preprocessing fitting plus **in-context support conditioning**, not gradient fine-tuning. The repository feature encoder preserves numeric columns and deterministically maps categorical values, using separate fitted codes for missing and unseen categorical values. Upstream TabDPT uses a training/support-fitted mean imputer for numeric missing values and standard scaling. If encoded feature width exceeds the loaded model's `max_features`, the upstream configured feature-reduction path is surfaced by the tutorials; `context_size` separately limits support rows used during prediction.

The E2E notebook reports input shape/missingness, class counts, model feature ceiling, whether feature reduction activates, requested context size, and the effective upper bound on support rows. The artifact-inference notebook reports the same serving-relevant capacity information for an externally supplied artifact and validates new numeric data so non-numeric or infinite values do not silently become imputed values.

## Artifact contract and trust boundary

The reusable DIMER serving state includes the labelled support table, the fitted class-label mapping (`classLabels`, sorted order defines the probability column order), fitted repository encoder state, fitted upstream imputer/scaler state, any fitted PCA basis needed for wide tables, and the exact pinned base-model contract.

`export_artifact_bundle()` emits an explicit v3 release artifact. `validate_artifact_bundle()` checks artifact format/task, class-label mapping, fitted preprocessing consistency, support-table path/size/SHA-256, and the declared base-model repository/revision/filename/digest/upstream commit before model loading. `load_verified_artifact()` reconstructs new release artifacts from saved fitted preprocessing state **without fitting those preprocessing statistics again**.

Established older `tabdpt-dimer-context-v3` manifests that predate the additive explicit version/semantics/size fields remain compatible. If such an artifact lacks the complete fitted upstream preprocessing state, `load_verified_artifact()` may use the legacy reconditioning compatibility path and sets `preprocessing_restored_ = False`. That fallback is retained for compatibility but **must not be used as release-grade artifact-inference evidence**; the external-artifact section fails closed when it encounters that path.

The E2E notebook exports `artifact.json` and `training_context.parquet` under `outputs/artifact/`, copies them across a fresh filesystem boundary, reconstructs the serving pipeline through the verified no-refit path, and checks that reloaded `argmax` labels are identical and class probabilities are equivalent within tolerance. The export stage also writes `outputs/tabdpt_classifier_artifact.zip`, a deterministic ZIP of `outputs/artifact/` (the two members at its root in sorted order, each with the timestamp 1980-01-01 00:00:00 and mode 0644, written atomically), and prints its SHA-256 as the trusted digest. The external-artifact section never uses this run's export; it uses the pinned release asset, which has exactly that layout. The script-built `examples/sample-artifact/` bundle and `tools/build_sample_artifact.py` were removed: a bundle assembled by a script that does not run the notebook's export stage does not meet SART9.

Digest and manifest checks establish internal consistency with this repository's contract; they do not authenticate the sender. The release artifact format is Parquet context plus JSON metadata, carried in a ZIP of exactly those two members, and does not accept pickle or arbitrary Python-object payloads. Because `training_context.parquet` contains labelled support data, treat an exported artifact with the same confidentiality, licensing, retention, and disclosure controls as its source dataset.
