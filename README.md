# TabDPT Classifier Pipeline

DIMER-ready inference pipeline for **TabDPT v1.2 (TabDPT-Turbo)**, an open-weight tabular foundation model from Layer 6 AI for in-context supervised learning.

## What this repository provides

- supervised tabular **classification** with `TabDPTClassifier`;
- train-fitted preprocessing for mixed numeric/categorical CSV tables;
- immutable upstream weight provenance and SHA-256 verification;
- a DIMER manifest plus executable local/on-prem runtime adapter;
- deterministic validation splitting and support-row capping from DIMER runtime controls;
- a DIMER Notebook Specification 3.0 **standalone** `E2E` tutorial (generated by `tools/build_notebook.py`; see [`tutorials/README.md`](tutorials/README.md)) with a verified no-refit artifact reload and a closing external-artifact section, plus CI tests that do not download the 254 MB model in routine CI.

The weight bytes are not committed to this repository. Runtime acquisition is pinned to the immutable Hugging Face revision and verified before model construction. The local snapshot layout is `weights/tabdpt-1.2/` (the `MODEL_KEY`): the committed `dimer-base-manifest.json` there lists the checkpoint's path, byte size and SHA-256, `stage_missing_files` fetches only what is absent at the pinned revision, `verify_snapshot` re-hashes every entry, and `TabDPTClassificationPipeline.from_pretrained(weights_dir=...)` pins the verified file as the base checkpoint (see [`weights/README.md`](weights/README.md)).

## DIMER runtime contract

DIMER's current tabular transport is reused rather than inventing a new channel:

- `datasetPreprocessing` → `DIMER_PREPROCESSING_ARGS_JSON`
- `modelFinetuning` → `DIMER_HYPERPARAMETERS_JSON`

For TabDPT, `modelFinetuning` is a compatibility transport namespace only. `fine_tune` must remain `false`; the other fields control ICL context/inference (`n_ensembles`, `context_size`, `batch_size`, `temperature`, `seed`). Every manifest key is consumed by `tabdpt_classifier_pipeline.dimer_runtime`, and CI checks the manifest/runtime key sets for exact equality.

`dimer_entrypoint.py` reads `DIMER_DATASET_DIR`, accepts `train.csv` plus optional `val.csv` directly or inside one ZIP, applies the requested validation split/support cap, executes TabDPT, and writes `result.json`, `training_context.parquet`, and `artifact.json` under the configured output paths.

## Quick start

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e '.[model]'
```

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from tabdpt_classifier_pipeline import TabDPTClassificationPipeline

frame = load_breast_cancer(as_frame=True).frame
train, test = train_test_split(frame, test_size=0.2, random_state=42, stratify=frame['target'])
pipe = TabDPTClassificationPipeline()
pipe.fit(train, target_column='target')
print(pipe.evaluate(test))
```

For DIMER, mount/cache the verified base weight through `DIMER_BASE_MODEL_PATH` so execution does not depend on live internet access.

## Tutorials

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/kurtvalcorza/tabdpt-classifier-pipeline/blob/main/tutorials/tabdpt_classifier_colab.ipynb)

`tutorials/tabdpt_classifier_colab.ipynb` (`E2E`) is declared under DIMER Notebook Specification 3.0 and is **standalone** (§4) and `GUIDED`: generated by `tools/build_notebook.py`, it carries the package's three modules verbatim, a stage runner, the model identity, the snapshot manifest digests and a hash-locked requirements file (`tutorials/requirements-colab.lock.txt`) that a pinned `uv` installs into an isolated environment (nothing is installed into the kernel, so `Run all` needs no restart), so the exported notebook runs without this repository (parity enforced by `tests/test_notebook_parity.py` and `tools/validate_release_assets.py`). The E2E default path loads scikit-learn's bundled breast-cancer table (no download), validates it with `validate_inputs` into an input manifest, splits it with class coverage preserved, compares `majority_class_baseline`, conditions the model, writes an `evaluation_report` (`sample-sanity`: accuracy / log loss / ROC-AUC on one seeded holdout), scores new rows with class probabilities under an explicit `argmax` rule, exports JSON/CSV plus the DIMER serving artifact (a directory and a deterministic ZIP), and reloads it across a fresh boundary without refitting preprocessing. It then closes with an external-artifact section (Section 10, NOTEBOOK_SPEC 3.0 §19.1): it downloads the pinned sample artifact `tabdpt_classifier_artifact.zip` from the release `sample-artifact-breast-cancer-v1` (v1: packed on the VM after a recorded hosted T4 run of this notebook's default path at `762eb5b`, from that run's exported `outputs/artifact/`, which does not meet SART9 under the owner ruling of 2026-10-22; it stays pinned until `sample-artifact-breast-cancer-v2`, the ZIP the export stage writes in a recorded run, is published and pinned; never the current run's export), checks its SHA-256 before extraction, validates it with `validate_artifact_bundle` and the breast-cancer data contract, rebuilds serving state with `load_verified_artifact` (no preprocessing refit, the checkpoint Section 3 verified) and scores eight holdout rows into `outputs/external_artifact/`. The separate artifact-inference companion was retired under NOTEBOOK_SPEC 3.0 (KND11). BYOD is optional and gated off by default. See `tutorials/README.md` for the registry and `docs/release-verification.md` for the release gate.

## Evaluation caveat

TabDPT was pretrained on real-world tabular datasets. Public tutorial/benchmark datasets may overlap directly or indirectly with upstream pretraining. Tutorial metrics are plumbing/sanity checks, not clean evidence of out-of-distribution quality.
